# L3 操作卡 —— Windows 起不来时怎么办

> 这张卡是给**人**看的，不是给脚本看的。
> 目标：在系统起不来、甚至盘有坏道的情况下，**把证据取出来并带走**，
> 然后在一台能用的机器上分析。
>
> 一句话原则：**errwatch 不修物理坏盘，它负责"看清发生了什么"并把证据搬运出去。**

---

## 一、先分清两种情况（这决定你要走哪条路）

| 情况 | 表现 | 该怎么走 |
|---|---|---|
| **逻辑损坏** | 能进 WinRE、能看到 C 盘、文件读得出来；只是启动不了、蓝屏循环、更新失败 | 直接 **第二节**：在 WinRE 里采集 |
| **物理损坏 / 盘半死** | 读文件卡住、报 IO 错误、听到异响、盘时有时无 | 直接 **第三节**：先镜像再分析，**不要**在坏盘上反复读 |

**最要紧的一条**：盘一旦有物理损坏迹象，**第一件事是停止对它写入**（不要 chkdsk /f、不要重装、不要"修复"），
先做只读镜像。每一次失败的重试都在加重损伤。

---

## 二、逻辑损坏：在 WinRE 里采集（约 5 分钟）

### 1. 准备

- 一个 **U 盘**（空的最好，格式 FAT32 或 NTFS 都行，容量几百 MB 足够）
- 建议从微软官网的"媒体创建工具"做一个 **Windows 安装 U 盘**（它的修复模式就是 WinRE）
- 如果有恢复分区，也可以直接从恢复分区进（开机按厂商键）

### 2. 进 WinRE 的三条路

1. **强制关机法**（不需要任何介质）：开机出现厂商 logo 时按住电源键 5 秒强制关机，重复 **3 次**，第 4 次开机应自动进入"自动修复" → 高级选项 → 命令提示符
2. **安装 U 盘**：从 U 盘启动 → 左下角"修复计算机" → 疑难解答 → 高级选项 → 命令提示符
3. **恢复分区**：开机按厂商恢复键（不同品牌不同）→ 疑难解答 → 命令提示符

进去后是 `X:\Sources>` 这样的提示符 —— 注意 **X: 是内存盘，不是你的系统盘**，你的系统大概率还是 `C:`。

### 3. 跑采集器

把 errwatch 目录拷到 U 盘（或另一个可用的盘上），假设它在 `E:\errwatch`：

```cmd
E:
cd \errwatch\runners
L3-collect.cmd  E:\bundle  C:
```

参数含义：第一个是**证据包输出目录**（放在 U 盘上，别放 C 盘），第二个是**目标系统盘**。

可选开关：

| 开关 | 作用 |
|---|---|
| `--chkdsk` | 额外做 `chkdsk C: /scan`（**只读扫描**，不改盘，但很慢） |
| `--dumps` | 额外拷贝内存转储（`MEMORY.DMP` 可能几个 GB） |
| `--full` | 连 WER 报告内容一起拷（默认只列清单） |

**WinRE 里你天然是管理员**，所以需要提权的项（diskpart / dism / 离线注册表）都会自动执行；
如果在正常 Windows 里用普通账号跑，采集器会把这些项**跳过并如实记进 manifest**，不会假装成功。

### 4. 判断有没有采到关键东西

采集结束后打开 `bundle\manifest.json`（记事本就行），重点看：

- `missing` 数组**空不空** —— 缺的东西往往比有的东西更重要，尤其：
  - 缺 `System.evtx` / `Application.evtx` → **事件日志没取到，后面分析会很空**
  - 缺 `SrtTrail.txt` → 说明这台机器没触发过启动修复（或者系统盘不是你以为的那个）
  - 缺 `registry` / `packages` → 多半是权限或 hive 路径不对
- `items` 里每个条目的 `sha256` —— 这是证据指纹，可用来核对搬运途中有没有被改动

## 三、物理损坏：先镜像，再分析

**errwatch 在这里只做两件事**：告诉你该找什么工具、分析镜像里的证据。它**不做数据恢复**。

### 正确的顺序

1. **停机**：关掉那台机器，避免继续写入
2. **镜像**：用只读方式把盘对拷出来 —— 不要直接对拷到同一块盘
   - 工具路由：`ddrescue`（Linux，最稳，可断点续做）、`DiskGenius`（Windows，图形界面，支持坏道跳过）、硬盘厂商的诊断/克隆工具（希捷 SeaTools、西数 Data Lifeguard 等）
   - 关键参数：**跳过坏道、只读、可断点续做**，而不是"边读边修"
3. **备份镜像**：镜像文件本身也要有一份备份（它是你唯一的证据来源了）
4. **在镜像上做取证**：把镜像挂载成盘符（或恢复到一块新盘），然后对它跑 `L3-collect.cmd` —— 目标盘指向镜像挂载的盘符
5. **分析**：见下一节

### 明确不归 errwatch 管的部分

- 盘片物理损伤、磁头故障 → **数据恢复服务**（先问清报价与"不成功不收费"）
- 固态盘主控挂掉（盘完全不出现在系统里）→ 同上
- 这类情况 errwatch 不会假装能帮上忙 —— 它的原则是「能安全做的才做，超出的明确告诉你找谁」

## 四、把包拿到另一台机器上分析

证据包是**自描述**的（全部信息在 `manifest.json` 里），所以搬到哪都行：

```powershell
pwsh -File errwatch-bundle-analyze.ps1 -Bundle E:\bundle
```

- 分析器**只读证据包，不碰原机器** —— 在另一台电脑、恢复后的系统、便携 PowerShell 上都能跑
- 加 `-OutFile 报告.md` 指定输出位置；加 `-Json` 输出结构化结果
- 规则来自 `core\rules.json` + `core\events.json`：**补了规则可以用同一个证据包重跑**，证据不变、结论更新

报告会明确区分「有证据支持的结论」和「没证据所以不猜」的部分，并列一份**证据缺口**清单。

## 五、常见误解

| 误解 | 事实 |
|---|---|
| "采不到就是不重要" | 相反：采集器把取不到的项**全部**记进 `missing`，缺口本身是证据 |
| "在坏盘上多跑几次 chkdsk 就好了" | `chkdsk /f` 会**写盘**。物理损坏时这是加重损伤 |
| "采到的东西必须马上分析" | 不必。证据包可以放几个月，规则更新后重跑即可 |
| "分析器要装在我的系统上" | 不用。它是单文件 + `core\`，U 盘上就能跑 |
| "errwatch 能救数据" | 不能。它取证据、给路由；物理恢复要找专业手段 |

## 六、与其它等级的关系

```
L1 正常看护        errwatch.ps1            ← 日常
L2 安全模式诊断    errwatch.ps1（降级）    ← 能起来但不全
L3 恢复环境取证    本卡                   ← 起不来
```

想看当前机器处在哪一级、该走哪个入口：

```powershell
pwsh -File errwatch-level.ps1
```
