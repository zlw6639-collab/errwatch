## 一、先说结论

两项 P0 都已落地，且**在做的过程中抓到一个比它们更严重的真 bug（P0，丢事件级）**：

> 哨兵会**把还活着的进程误报成「刚退出」**，而且这条假事件会占满 5 分钟去重窗口，
> 把**真正的退出挡掉** —— 表现为「有通知，但通知的是错的；真出事时反而没通知」。

这个 bug 在 `-ah` 之前的任何一个包里都存在（`test-sentinel` 原来 6 个用例都没覆盖「进程持续存在连续两次扫描」这个最基本场景）。

## 二、P0-2：监视覆盖声明

### 状态定义（只回答「这段时间看没看到」，不是诊断结论）

| 状态 | 给用户的话 | 触发条件 |
|---|---|---|
| `MONITORED` | 监视正常 | 进程出现后一直在看 / 当前没运行但退出已被记录 |
| `NOT_RUNNING_AT_START` | 启动时未运行 —— 之前崩过也抓不到 | 本轮监视开始前它就不在运行 |
| `MONITOR_GAP` | 监视有缺口 —— 退出时刻和原因都不确定 | 两次检查间隔 > `gapAfterSeconds`（默认 180 秒） |
| `OBSERVATION_UNCERTAIN` | 观测不确定 —— 分不清是不是同一个实例 | 取不到 `StartTime` / 缺口期间才出现 |

### 落在哪

- 事件字段：每条 `ProcessExit` / `NotResponding` 带 `coverage` + `coverageReason`
- 目标级状态：`sentinel-coverage.json`（`targets[]`，含 `firstSeenAt` / `lastSeenAt` / `instances`）
- `-Status`：输出 `coverage` / `coverageSince` / `integrity`
- 托盘：待处理菜单项后缀 `〔监视有缺口〕` 等；气泡文案在缺口时改口（「退出时刻不确定」），不再说得像「刚刚精确崩了」
- `core\sentinel.json` 新增 `gapAfterSeconds`（默认 180）

### 为什么是「间隔」而不是「进程启动时刻」

`-Once` 模式每次都是新进程，用「哨兵进程启动时间」判定会永远错。所以用 **coverage 文件的 `lastCheckAt`** 做「上一轮什么时候看的」：
常驻 `poll=1` 秒时不会触发；机器睡眠、进程被挂起、计划任务每 2 分钟拉一次才会触发 —— 正好是要报缺口的场景。

## 三、P0-3：启动完整性

- **原子写**保留（`.tmp` → `Move`）
- **损坏可恢复**：pending 解析失败 → 先备份成 `sentinel-pending.json.corrupt-<时间戳>`，再交给事实记录重建
- **投影重建**：每次同步以 `sentinel-events.jsonl` 为底座合并，剔除
  - 已被托盘 ack 成终态的（`launched / acknowledged / expired`）
  - 超过 7 天的
  - 缺 `id/type/time` 的
- **宁可重复不可丢**：pending 里有、事实记录里没有的事件也保留（合并而非覆盖）
- **内容没变就不写盘**（常驻 poll=1 秒，避免无意义 IO）；每 60 轮兜一次校正，防外部改坏后没人发现
- 结论写进 `sentinel-coverage.json` 的 `integrity`（`repaired` / `corruptionBackup` / `kept` / `droppedTerminal` …）

## 四、顺带抓到的真 bug（P0，丢事件级）

### 现象（实测）

同一个进程一直在运行，连续两次扫描：

```
--- run 2 --- events=0
--- run 3 --- events=1      ← 进程还在，却报了 ProcessExit
```

更糟的是随后这次「真退出」：

```
--- set gap then kill ---
--- run 4 --- events=0      ← 真退出被 5 分钟去重窗口挡掉了
```

### 根因

`Get-Snapshot` 里 `StartTime` 是 **ISO 字符串**；写进 `sentinel-last.json` 再 `ConvertFrom-Json` 读回来会变成 **DateTime**。
实例身份用 `"$pid|$startTime"` 拼字符串比较 → 两边文本永不相等 → 每轮都把「还在跑的实例」当成新出现的、把上一轮的实例当成「已退出」。

假事件进 `recent` 去重记忆后，真退出 5 分钟内同 key 被判定「刚报过」→ 静默丢弃。

### 修法

新增 `ConvertTo-InstanceTime` / `Get-InstanceKey`，**所有实例身份比较统一走它们**（退出检测、卡死计数、事件去重 key、事件字段写入）。
JSON 往返、旧格式（zh-CN 时间串）都能归一成同一 ISO 文本。

## 七、已知边界（本轮没做）

1. **报告 / UI 两个入口还不消费 coverage** —— 只有 `-Status` 和托盘在读，用户在 UI 里仍看不到「这次看没看住」
2. **事件级 coverage 不回填历史** —— 只按「本轮有没有缺口」判定，更早的缺口不补写进已入队事件
3. **`sentinel-events.jsonl` 半行 JSON 是跳过不是报错**，`integrity` 里也没这一项计数（事实记录自身只做到「能读的读出来」）
4. **缺口与救援未联动** —— 缺口时仍会推荐救援，只是文案加了提示
5. **覆盖判定只到轮次级** —— 识别不出「进程还在、采样被冻住」这种隐蔽情况；会保守地说「有缺口」，但不会更细
6. **仍是合成夹具** —— 没有真实 CAD / PICO 的崩溃与恢复样本，本报告不宣称验证了真实应用的恢复能力
