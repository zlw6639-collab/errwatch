# 审计：有限自动兜底（2026-10-24，契约 §十一）

> 用户要的是「用户没回应时，系统别干等着」。我们的落法是：**超时不等于授权**——
> 到期只做两件事：**让事件更显眼** + **留一条审计**。不碰文件、不碰进程。

## 一、为什么把动作白名单写死在代码里

方案 §二 说「超时不等于用户同意所有操作」。如果允许用户在 `settings.json` 里打开
「到期自动结束进程」，这条边界就成了一句空话 ——

- 进程「无响应」可能只是暂时忙（CAD 保存大图、PS 渲染）；
- 用户可能只是切到了别的桌面；
- 一旦误判，**结束进程 / 覆盖文件是不可撤销的**。

所以 `core\fallback.ps1` 里两组常量：

```powershell
$script:EwFallbackAllowedActions  = @('notify-only', 'open-ui')          # 允许
$script:EwFallbackForbiddenActions = @('delete','overwrite','move',
                                       'kill-process','restart','system-change')  # 永远不许
```

配置只能选**提示方式**，不能扩大动作范围。测试 C 用例逐个断言：
`delete / kill-process / restart / overwrite / move / system-change / auto-fix` 全部被拒。

## 二、判定与去重

| 规则 | 实现 |
|---|---|
| 计时起点 | `event.time`（**被发现的时间**），不是用户上次看到的时间 |
| 用户已处理 | `lifecycle` 终态 → 不升级（不变式 3） |
| 到期阈值 | `settings.json` 的 `autorespond.deadlineMinutes`（默认 30，范围 5–1440） |
| 去重 | `tray-fallback.jsonl` 里有该 id 就不再升级（不变式 2：不会越等动作越强） |

## 三、接线（托盘）

| 位置 | 行为 |
|---|---|
| 菜单项 | 追加 `[⏰ 超时 N 分钟]` 标记 |
| 常驻循环 | 新到期的 → 写一条审计 + 弹一次气泡（文案明说「不会自动执行任何操作」） |
| `-Check` | 输出 `overdueCount` / `overdueTexts` / `deadlineMinutes`（便于自动化验证） |
| 白名单 | 读配置后再过一遍 `Test-ErrwatchFallbackActionAllowed`，配置被手改也不放行 |

## 四、真实验证（不是只跑单测）

用 `-StateDir` 造了真实 pending，跑 `tray -Check -Json`：

| 事件年龄 | `overdueCount` | 菜单文本 |
|---|---|---|
| 10 分钟 | **0** | `demo2.exe · unknown-exit · 01:11:05` |
| 45 分钟 | **1** | `demo2.exe · unknown-exit · 00:36:07　[⏰ 超时 45 分钟]` |

也就是说：判定、菜单标记、`-Check` 输出三条路都通了。

## 七、剩余（诚实记录）

1. **`open-ui` 动作只被允许、还没实现**：现在到期一律走「提示」，`open-ui` 只是白名单里的一个合法值，
   没有代码去主动打开主界面（那会抢焦点，需要单独设计）。
2. **气泡受全屏/静默策略**：全屏时不弹气泡，但菜单标记与审计照做 —— 这一点符合 §二「全屏时保留事件」。
3. **只升级一次就停**：契约 §十一 去重是「同一事件只升一次」，没有「越久越频繁」的梯度（不变式 2 要的就是这个）。
4. 没有做「用户已读但未处理」的区分：点了菜单打开救援就记 `rescue=launching`，但不算处理完。
