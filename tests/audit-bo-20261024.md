## 五、发现的问题

### P2-1｜自家门禁在全新解压上跑不绿（test-doctor C 非密封测试）

- 实测：在解压出的干净目录跑 `tests\run.ps1` → **EXIT=1**，失败项 `test-doctor.ps1` Case C「哨兵心跳必须单独一行」。
- 根因：Case C 断言 doctor 输出必含 `哨兵心跳` 且匹配 `秒前|心跳停在`。但 doctor 在**哨兵从未跑过**（全新安装/解压，无 sentinel-status.json）时走 L373 分支，输出 `[未跑过] 没有 sentinel-status.json（哨兵从没起来过）`——语义上完全正确，但不满足测试正则。
- 为什么他们没发现：开发目录里有真实 state 文件 → 心跳分支命中 → 测试绿。**测试依赖了开发机的状态**，不是密封的。
- 影响判定为 P2 的原因：这是**送审包**。审阅者解压后第一件事就是跑 `tests\run.cmd`（NEXT-SESSION.md 明说"直接双击"），拿到 EXIT=1 + FAIL，和文档宣称的 "门禁 EXIT=0 / doctor 8/8" 直接矛盾——可信度受损的不是功能，是整套自审叙事。
- 修法（任一）：① Case C 的正则放宽为 `'秒前|心跳停在|未跑过'`；② doctor 的未跑过分支文案改成以「哨兵心跳：」开头（顺带满足文案统一）；③ test-doctor 用隔离 state dir 跑。①最省事。

### P2-2｜真实运行数据误打包进送审包

- 包根目录含 `tray-fallback.jsonl`——**用户真机的兜底审计记录**：7 条，含 QQ、DSH Desktop、雷神加速器（leigod_launcher）、TabTip、start_protected_game、PhanteksNexLinq、真实时间戳（2026-10-24 21:41–22:59）与真实事件 id。
- 这轮特意把 -ay 里误打包的状态文件删了，但 `tray-fallback.jsonl` 是本轮 fallback 功能新引入的落盘文件，不在打包排除清单里 → 又漏了。
- 同类：`tests\_gate-b12.txt`（门禁输出残留，无害但属垃圾文件）。
- 修法：pack/verify-package 排除清单补上 `tray-fallback.jsonl`（以及所有 jsonl 状态文件的白名单化——"允许进包的名单"比"排除名单"更稳）。重打包后哈希链全部要重算。

### P3-1｜uninstall.ps1 的进程匹配会误杀编辑器

- L73-74：`$_.CommandLine -match 'errwatch-(sentinel|tray|ui)\.ps1'`，注释写「按命令行精确匹配，不碰别的 PowerShell」——**实际是子串正则，不是精确匹配**。
- 任何命令行里带这些文件名的进程都会被 `Stop-Process -Force`：典型如 `notepad.exe E:\...\errwatch-tray.ps1`（正在看源码的记事本）、`code ...\errwatch-tray.ps1`。**强杀编辑器丢未保存内容，恰好违背这个项目最核心的价值主张**（保住用户未保存的工作）。
- 修法：匹配收紧为 `powershell|pwsh` 可执行 + 命令行含 `-File` 且参数以 errwatch-*.ps1 结尾；或用 `-match '-File\s+"?[^"]*errwatch-(sentinel|tray|ui)\.ps1'`。

### P3-2｜retention 不清理 tray-fallback.jsonl

- `core\retention.ps1` 的清理清单没有 `tray-fallback.jsonl`（0 处引用）。按 id 去重做得对（不会每 tick 爆炸增长——上轮的静默 ack 教训吸收了），但每个新超时事件一行、**永不清理** → 慢性无界增长。它也是 P2-2 的成因：文件一直躺在项目根，打包时顺手就进去了。
