# 演练：浩辰CAD 2027 真实崩溃（2026-10-24 20:07，C1）

> 这是 **C1 的第一次真实演练**，也是 `recover.json` 里 `gstarcad` 条目的首次现场验证。
> 全程只读 + 只复制，没有修改用户的 `.dwg` / `.sv$`。

## 一、现场

| 项 | 值 |
|---|---|
| 程序 | 浩辰CAD 2027 简体中文（GstarCAD，**不是** AutoCAD） |
| 主程序 | `D:\cad\浩辰CAD 2027\gcad.exe`，进程名 `gcad` |
| 自动保存位置 | `%LOCALAPPDATA%\Temp`（注册表 `SAVEFILEPATH`，实测一致） |
| 自动保存间隔 | 用户按提示把 `SAVETIME` 设为 1 分钟 |
| 图纸 | 未命名新图（`Drawing1`），画了三圆 + 线，**未保存** |

## 二、时间线（毫秒级）

| 时刻 | 事件 |
|---|---|
| 20:07:19 | 自动保存写出 `Drawing1_1_000002E14C138010_4417.sv$`（40.7 KB） |
| 20:07:42.066 | `Stop-Process -Id 22128 -Force`（模拟崩溃：无退出码） |
| 20:07:43.118 | 哨兵记录事件，**发现延迟 1052 ms** |

## 三、工具给出的判定

```
app      : gcad
verdict  : unknown-exit       ← 强杀没有崩溃证据，符合设计（不硬说成 crash-suspected）
coverage : MONITORED          ← 退出发生在监视过程中，时刻可靠
latency  : 1052 ms
来源     : observed           ← 不是 after-gap（没有跨盲区污染）
```

**这一条同时验证了两件事**：
1. `gcad` 已被纳入监视目标（此前**不在**，是这次现场抓出来的缺口，已修）；
2. `latencySource` 字段工作正常 —— 这次是 `observed`，`p50/p95` 会正常吸收，不会被当成盲区样本。

## 四、救援结果

| 项 | 结果 |
|---|---|
| 候选数 | **1**（分档「本次会话（最可能是你刚丢的那份）」） |
| 候选路径 | `C:\Users\<用户>\AppData\Local\Temp\Drawing1_1_000002E14C138010_4417.sv$` |
| 复制 | `-SaveTo D:\cad-rescue-test` → 成功，40.7 KB |
| 完整性 | 原件与副本 SHA256 一致（`4DD9006E77C25BA2…`）→ **原文件未被改动** |
| 文件格式 | 文件头 **`AC1032`** = DWG 2018 格式 → 改名 `.dwg` 理论上可直接打开 |
| 交付物 | `D:\cad-rescue-test\Drawing1-from-sv.dwg`（副本改名，供肉眼核验） |

`AC1032` 这条很关键：它证明 `.sv$` **不是私有格式**，而是完整 DWG 容器 ——
所以 `recover.json` 里「复制 → 改名 `.dwg` → 打开」这条指引对浩辰是成立的（此前只是照 AutoCAD 类推，现在有实测）。

## 五、结论

**已确证**（C1 的两个未知里，第一个已答一半）：

1. ✅ 浩辰的自动保存在 `%LOCALAPPDATA%\Temp`，命名 `<图纸名>_<n>_<序列>_<数字>.sv$`
2. ✅ `.sv$` 是 **DWG 容器（AC1032）**，改名 `.dwg` 的路径成立
3. ✅ 哨兵对 `gcad` 的发现延迟 **1.05 秒**，判定 `unknown-exit` + `MONITORED`（诚实：不冒充崩溃）
4. ✅ 救援只复制、不改原文件（SHA 比对一致）

**待用户肉眼确认**：
- 用浩辰CAD 打开 `D:\cad-rescue-test\Drawing1-from-sv.dwg`，看三个圆 + 那条线在不在、缺不缺最后一段

**仍未确认**：
- `SAVETIME` 是否可被工具从外部读到（注册表里确实没有该值）→ 目前仍只能靠「最近有没有产生过 `.sv$`」这个行为证据

## 五之二、用户确认（2026-10-24 20:1x）

> 用户打开 `D:\cad-rescue-test\Drawing1-from-sv.dwg` 后确认：**画的内容还在**。

**C1 前半段结案**：`.sv$ → 复制 → 改名 .dwg → 打开` 这条路径在本机浩辰CAD 2027 上**实测成立**，救回的是完整可打开的 DWG。

因此：
1. `recover.json` 里 gstarcad 的 `convert` 指引**定稿**（不需要把「图形恢复管理器」提为唯一首步）；
2. 自动保存间隔的实测建议：**1–2 分钟**（这次设 1 分钟，20:07:19 落盘，20:07:42 崩溃 → 只可能丢最后 23 秒内的笔画）；
3. 操作路径实测有效：**命令行直接输 `SAVETIME`** 比翻 OPTIONS 快得多 —— 已写进 `howToEnable`。

## 六、这次演练顺带抓到的两个缺口（都已修）

| 缺口 | 影响 | 修法 |
|---|---|---|
| `gcad` **不在** `core\sentinel.json` 的监视目标里 | 崩溃了没人报（比"救不回"更严重） | 加独立组 `[gcad, gstarcad]`（与 AutoCAD 不同产品，不互为兄弟） |
| `recover.json` 只认 AutoCAD（match + `acad.exe` 路径） | 找不到浩辰的恢复文件 | 加 `gstarcad` 条目（match `gcad/gstarcad/浩辰`，install 认卸载项「浩辰CAD」） |

> 教训（进 D 类）：**「装了国产替代品」这件事，工具必须先在现场看得见**。
> 这两个缺口都不是代码 bug，而是**配置假设过期** —— 而它们一个让「发现」失效、一个让「救援」失效，
> 恰恰是这个项目的两条腿。以后新装/换软件时，先跑一次 `errwatch-doctor` 看响应链和恢复机会两段。
