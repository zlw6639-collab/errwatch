## 五、新发现（3 个，全在新增脚本）

### P2-1　托盘常驻循环 ② 段缺全屏守卫，通知事件的 ack 语义被污染（已实测复现）

`errwatch-tray.ps1:302-308`：注释写「全屏：记 suppressed」，但 `foreach ($e in $decision.live)` **无条件执行**，没有 `if ($decision.action -eq 'suppress')` 守卫。结果每条正常通知的事件都会先被记一条 `suppressed`、45ms 后再记 `attempted`。

实测（构造一条 acad 待处理事件，托盘跑 7 秒，无全屏）：
```
{"id":"test0001","status":"suppressed","at":"...38.587"}   ← 伪造的抑制记录
{"id":"test0001","status":"attempted","at":"...38.632"}
```
因 Read-Acks 后写覆盖，终态碰巧正确，所以现有 10 个测试全过也没抓到；但 ack 审计轨迹已失真（每次通知都伴随一条从未发生过的"全屏抑制"），且为未来「suppressed 变终态」埋下通知失效的雷。
**修法**：② 段整体包进 `if ($decision.action -eq 'suppress') { ... }`。

### P2-2　托盘「打开主界面」在默认系统上打不开 UI

`errwatch-tray.ps1:273`：`Start-Process -FilePath ...\errwatch-ui.ps1 -WindowStyle Hidden` —— 直接对 .ps1 走 ShellExecute 默认关联。干净 Windows 上 .ps1 默认动词是"编辑"（记事本），**用户点菜单会打开记事本而不是主界面**。同文件 Start-Recover（:170-173）就 correctly 用了 `powershell.exe -File`，两处不一致。
**修法**：照 Start-Recover 写法，`powershell.exe -NoProfile -ExecutionPolicy Bypass -File errwatch-ui.ps1`。

### P3-1　静默应用（notify=false）事件的 suppressed ack 无去重，acks 文件无界增长

`errwatch-tray.ps1:299`：① 段对 `decision.silent` 每轮（2 秒）无条件 `Add-Ack 'suppressed'`，且 suppressed 非终态（设计如此，可补弹），事件永不离开 open 集 → 每个静默事件每天写约 4.3 万行。默认 notify.json 没有 notify=false 条目，属**用户一配置静默即触发**的潜在 bug。
**修法**：复用 ② 段的 `$suppressedIds` 内存去重（或把"策略静默"单独记一种终态）。

## 六、评价

- recover/sentinel/tray 三件套设计克制、边界写得清楚（recover 只读 + 白名单根 + 路径注入拦截；sentinel 退出≠崩溃、PID+StartTime 防复用、5 分钟去重；tray 通知状态机非布尔、可补弹语义），测试也各自到位。
- 三个 bug 有一个共同模式：**"防御写对了，守卫条件漏了"**（② 段缺全屏判断、① 段缺去重、主界面入口缺 powershell.exe 显式调用）。修起来都是几行的事。
