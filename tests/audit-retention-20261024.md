# 审计：保留策略（2026-10-24）

> 一句话：契约 §三 早就承诺「7 天滚动」，代码里却是**两套相反口径**——
> pending 按**事件发生时间**丢、acks **从不清理**。
> 现在统一为**唯一判据：事件进入终态的时间**。用户拍板的规则逐条落成测试。

## 一、动手前的事实（不是推测）

| 位置 | 原行为 | 后果 |
|---|---|---|
| `errwatch-sentinel.ps1` `Sync-Pending` | `if ((Now - t).TotalDays -gt 7) { droppedOld++; continue }` | 按**事件发生时间**丢：第 6 天才被处理的事件，第 7 天在待处理里消失 |
| `tray-acks.jsonl` | 只追加，无任何清理 | 文件一路长；读窗口 4000 行一旦溢出，早期终态读不到 → **已处理事件复活**（M60 遗留） |
| `STATE-CONTRACT.md` §三 | 写「体积按待办 26 的保留策略处理（7 天滚动）」 | 文档承诺 ≠ 代码事实 |

## 二、规则（用户 2026-10-24 拍板，逐条实现）

| 场景 | 规则 |
|---|---|
| 已结束的事件 | 终态进入时间超过 7 天 → 清事件记录 + **全部** ACK |
| 仍待处理的事件 | **不清**，无论发生多久 |
| 同一事件的多条 ACK | 按 id **整组**清 |
| pending 重建 | 用保留后的事件与状态重建，已处理事件不复活 |
| 日志损坏 | 单行坏只跳过并计数，不阻断整次清理 |

补充的两条保守规则（我加的，理由写进契约）：
- 旧数据终态行没有 `at` → 不清（无法证明它够老）
- 没有 ACK 的事件 → 不清（没人处置过 = 还需要人看）

## 三、实现

| 文件 | 改动 |
|---|---|
| `core\ack-state.ps1` | 聚合时新增 `lifecycleAt`：**终态进入时间**（因为已有「终态不回退」，记到的就是第一次进终态的时刻）。这是 7 天的唯一计时起点 |
| `core\retention.ps1`（新） | `Get-ErrwatchRetentionPlan`（纯判定）+ `Invoke-ErrwatchRetention`（执行）。逐行解析、坏行保留并计数、写 `.tmp` 再 `Move` |
| `errwatch-sentinel.ps1` | ① `Sync-Pending` 不再按事件时间丢，改记 `integrity.staleOpen`；② 每 6 小时最多清一次；③ 清理结果追加到 `sentinel-retention.jsonl` |
| `STATE-CONTRACT.md` | §三 改为「清理时整文件原子重写」；新增 **§九 保留策略**（含已知取舍） |

**并发保护**：`tray-acks.jsonl` 的写者是托盘，它随时可能 append。清理前后各取一次文件签名（长度 + 修改时间），中间变了就**跳过本次 ACK 清理**，下次再来。宁可晚清，不能覆盖托盘刚写的行。

**为什么由哨兵执行**：它是唯一常驻的后台进程；托盘不开时清理也不会停摆。
契约里登记为 `tray-acks.jsonl` 的**受控第二写者**——只在「确有终态超期」时发生，且整文件原子替换。

| A | 终态超 7 天 → 事件与 ACK 一起清，非终态的不受牵连 |
| B | 终态未满 7 天 → 不早清 |
| C | **仍待处理的事件 30 天前发生也不清**（本次改动的存在理由） |

## 七、剩余（诚实记录）

1. **真实数据还没有事件**：本机 `sentinel-events.jsonl` / `tray-acks.jsonl` 都不存在，
   所以这次清理在本机是零触发。规则由合成夹具看守，但**没有在真实积累的数据上跑过**。
2. **pending 的 100 条数量上限**仍在（防托盘菜单被撑爆）。超出时最旧事件退出**投影**，
   记录仍在 jsonl 里 —— 这与「因太旧而删除」是两回事，但用户看到的效果是「菜单里没了」。
   已写进契约 §九 的「已知取舍」。
3. **孤儿 ACK 不清**（acks 里存在、events 里已没有的 id）。担心读窗口截断导致误删，保守不动；
   代价是极端情况下 acks 里会留少量孤儿行。
