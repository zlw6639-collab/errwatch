# 换环境盲测（2026-10-23，给观察者用）

> 目的：验证「陌生人 + 别人的电脑」这个真实场景 —— 不是测诊断准不准（那有回归），
> 而是测**他能不能独立用起来**：启动 → 看懂结论 → 理解建议 → 知道下一步。
>
> 这是外部审计点名的 P1「陌生用户盲测」。**只有真人能做，工具替代不了。**

---

## 一、原则（很重要）

1. **不教学、不引导、不解释**。他问「这是啥」，你就说「你按自己的理解点点看，等下告诉我你看到了什么」。
2. **你只观察，不帮忙**。他卡住 30 秒也别提示 —— 卡住的地方才是数据。
3. **不要先跑一遍给他看**。要记录的是"第一次"。

## 二、准备（你来做）

1. 把整个 `errwatch-20261023-q` 文件夹拷到他电脑（U 盘 / 网盘 / 微信都行），**解压到任意位置**（路径带空格也可以，已做过预检）。
2. 告诉他：「双击文件夹里的 `启动报错看护.vbs`」。
3. 然后闭嘴，开始记。

> 已预检（2026-10-23）：打包内容在**含空格路径** + **PowerShell 5.1** 下，
> doctor / 报告 / UI 自检 / 修复器演练全部 exit 0。所以他那边大概率能跑起来。

## 三、给小伙伴的一句话

> 「帮我看看这台电脑有没有什么问题，这有个小工具，你点开看看，看懂了跟我说一下你看到了啥。」

不要多说。不要说「它会扫描日志」「它会给建议」——那是在教。

## 四、观察表（你填）

| # | 步骤 | 看什么 | 记录（他做了什么 / 说了什么 / 犹豫了几秒） |
|---|---|---|---|
| 1 | 打开后第一眼 | 先看哪？有没有困惑（标题？按钮？空表格？概览条？） | |
| 2 | 找「开始扫描」 | 找得到吗？找了几秒 | |
| 3 | 扫描等待 | 有没有以为卡住 / 反复点 | |
| 4 | 扫描完的弹窗 | 读完了吗？复述了什么 | |
| 5 | 列表 | 知道「状态」列（有说明/没说明）是什么意思吗 | |
| 6 | 点一行看详情 | 先看哪段？「结论状态 / 可信度」看懂了吗 | |
| 7 | 会不会点「生成修复」 | 点了之后他**以为**会发生什么 | |
| 8 | 会不会点列头筛选 | 发现这个功能了吗（没发现 = 隐藏太深） | |
| 9 | 最后问他 | 「你觉得这电脑有问题吗？如果有，下一步你会做什么？」 | |

## 五、常见情况预案

| 情况 | 怎么处理 |
|---|---|
| 他的电脑很干净 → 「本次扫描 0 条 / 没有发现异常」 | **这是正常结果，也是观察点**：他信不信？会不会觉得「是不是没扫到」 |
| 杀软/浏览器报「不认识的文件」 | 记录**原文**（误报是真实产品风险），不要当场辩解 |
| 他问「这个能修吗」 | 不回答，看他自己怎么理解「生成修复」 |
| 他没有管理员权限 | 记录能不能跑（只读模式应当能跑） |
| 他问「会不会改我电脑」 | 记录他怎么问的（说明「不改」这件事在界面上没说清） |
| 他看不懂中文术语（PICO/ucrtbase 之类） | 记录是哪几个词 |

## 六、结果怎么回填

1. 把观察表里的**卡点**整理成 3~5 条，写进 `HANDOFF.md` §三 A 第 7 项（真人盲测）。
2. 按项目原则（HANDOFF §四.9）：**「看不太懂」不等于规则判断错了** —— 优先改文案与入口，不改判定逻辑。
3. 如果出现「点了不该点的」「以为修好了其实没修」这类误操作，单独记一条，优先级高于文案问题。

## 七、已知边界（别指望这次覆盖）

- **未验证**：没有 `pwsh`、只有 5.1 的干净 Windows（5.1 语法已全量解析过，但没在纯净机上跑过）
- **未验证**：杀软拦截、非中文系统、高 DPI 缩放
- **未验证**：WinRE 恶劣环境（盘符重排 / BitLocker / 只读 / 断电 / 空间不足）—— 见 HANDOFF §三 A-8
- 本次盲测**不测**：诊断准确性、修复成功率（这两项有回归与独立验证覆盖）
