# 覆盖面盘点：能看到 / 能分析 / 能初步解决（真实数据）

- 日期：2026-10-22
- 起因：「网络报错能看到了，那外设？固态？软件？各种各样层出不穷的报错呢」
- 方法：拿本机**真实日志**按领域统计（只算关键/错误/警告，信息级本来就是正常记录），再对照我们已有的能力

## 一、真实分布（System 日志，Level 1/2/3，共 90 条）

| 领域 | 条数 | 主要来源 |
|---|---|---|
| **其他/噪音** | 52 | `DistributedCOM/10016` ×44、`Resource-Exhaustion-Detector/2004` ×6 |
| **外设/驱动** | **20** | `Kernel-PnP/219` ×13、`HidBth/2` ×5、`BTHUSB/12` ×2 |
| **软件/服务** | 11 | `Service Control Manager/7031` ×8、`7000` ×2、`7011` ×1 |
| **网络** | 7 | `WLAN-AutoConfig/10002` ×5、`NDIS/10317` ×1、`DNS-Client/1014` ×1 |
| **存储/固态** | **0** | ← 见下 |

**两条关键事实**：

1. **存储/固态在事件日志里是 0 条**。SSD 的健康问题**不写事件日志**（除非真出现 IO 错误/掉盘）——
   真正的健康数据在 **SMART** 里，而我们现在**没有采集它**。
2. `DistributedCOM/10016` 占了 52 条里的一大半，但它是**权限噪音**。
   我们的采法是"警告级只采事件表已收录的"，所以它**天然进不来** —— 这是刻意的，不是遗漏。

## 二、三层能力对照（诚实版）

| 领域 | ① 看得到？ | ② 能分析（人话）？ | ③ 能初步解决？ |
|---|---|---|---|
| **网络** | ✅ 刚补上 | ✅ DNS 1014 / NDIS 10317 | ⚠️ 只给建议（换 DNS、重插网卡），**不能自动修** |
| **软件/服务** | ✅ SCM 7031/7000/7011 | ✅ 已收录 | ✅ **能**：重启服务 / 重启进程（`fix` 已有） |
| **外设/驱动** | ✅ Kernel-PnP 219 | ⚠️ 219 有；蓝牙两条**当时未收录** | ✅ **能**：`rescan-devices`（重扫 PnP 设备） |
| **固态/存储** | ❌ 事件日志 0 条 | — | ❌ 不能（属硬件层，只能路由） |
| **固态健康** | ❌ **没采 SMART** | — | ❌ 只能路由给厂商工具 |
| **软件（非崩溃）** | ❌ **没采** | — | ⚠️ 部分 |

### ③ 修复能力到底有哪些

`errwatch-fix.ps1` 现有 **7 种动作**：
```
log-rotate, config-fix, check, rescan-devices,
list-problem-devices, restart-service, restart-process
```
覆盖的是「**重启 / 重扫 / 改配置 / 轮转日志**」。
**不碰**：硬件、驱动安装、注册表（除 config-fix 的字段改写）。

所以准确说法是：**能初步"处置"的只有服务与进程，其余是"看清 + 指路"。**

## 三、管理层看不到的三块（缺口清单）

### 缺口 1：Application 日志里"崩溃之外"的报错，我们只取了 Id=1000

实测 Application 日志里的错误/关键级来源：

| Provider | 条数 | 是什么 | 我们采了吗 |
|---|---|---|---|
| Application Error | 438 | 含 1000 崩溃 | ✅ 取了 1000 |
| **Microsoft-Windows-Perflib** | **65** | 性能计数器损坏 | ❌ |
| **VSS** | **57** | 卷影服务（备份/还原） | ❌ |
| **.NET Runtime** | **30** | **.NET 应用异常/崩溃** | ❌ |
| CertificateServicesClient-CertEnroll | 24 | 证书注册失败 | ❌ |
| **Application Hang** | 11 | 应用无响应（1002） | ❌（有规则没采） |
| **RestartManager** | 10 | 安装时**文件被占用** | ❌ |

→ 这块**投入产出最高**：全是普通用户真会遇到、且我们已有人话可写的东西。

### 缺口 2：不在事件日志里的信息源（需管理员权限）

实测（我这边以非管理员跑）：`Get-StorageReliabilityCounter`、`Get-PhysicalDisk`、
`Get-PnpDevice`、SMART WMI —— **全部被拒**。

→ 说明：**固态健康 / 设备状态**要靠这些接口，而不是事件日志。
它们**需要管理员权限**，应当在"以管理员运行"时采集，并明确标注"需管理员"。

### 缺口 3：L3 证据包里还没覆盖这些新领域

刚补的 System 日志采集只加进了 `errwatch.ps1`（L1）。
`runners\L3-collect.cmd`（WinRE 取证）目前采的是事件日志原件 + 启动证据，
还没针对"外设/固态"补采集项（如 `Get-PnpDevice` 快照、SMART 数据）。
